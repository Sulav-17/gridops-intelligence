Objective

Build the production forecasting and MLOps foundation for GridOps Intelligence.

M05 must train, evaluate, select, persist, and prepare production forecasting candidates using the leakage-safe M04 feature snapshots, baselines, backtesting framework, and metric logic.

M05 is not the alerts, scenarios, dashboard, briefing, or deployment milestone.

Completion Statement

M05 succeeds when a production forecasting candidate is trained reproducibly, compared against verified M04 baselines, selected through explicit gates, persisted with lineage, and exposed through safe forecast-output contracts without claiming unsupported production performance.

M05 should leave the repository ready for M06 alerts, scenarios, and briefings.

Included Scope

Non-Negotiable Rules

Every model must use only point-in-time-safe features from M04.

No random train/test splitting is allowed.

A production candidate must be compared against M04 baselines.

No model can be promoted without reproducible metric evidence.

No forecast output can claim operational authority.

No future target actuals may be used as features.

No scheduled inference should be presented as production scheduling unless actual scheduling infrastructure exists and is tested.

No MLflow registry or model registry should be added unless it is kept simple, tested, and clearly inside M05 scope.

Candidate Models

M05 should implement a simple production candidate first.

Preferred order:

sklearn tree or gradient-boosting candidate if safest
XGBoost or LightGBM only if dependency and runtime risk are acceptable
quantile model only if it can be implemented safely without overexpanding scope

The model must remain reproducible.

Model training must use time-based windows only.

Hyperparameter tuning is optional and should be avoided unless it stays simple and deterministic.

Do not build a complex model zoo.

Do not add deep learning.

Do not claim the candidate is production grade unless evidence supports that exact claim.

Quantile Forecasting

M05 may add P10, P50, and P90 schema and simple quantile output support.

Implementation options:

store P10, P50, and P90 fields even if only P50 is populated at first
train separate quantile-capable models only if safe
defer true quantile modeling honestly if it becomes too large

If quantile values are not genuinely produced, they must be nullable and documented as not implemented.

Do not fake prediction intervals.

Model Selection Gates

M05 must implement explicit model-selection gates.

A model-selection gate should compare the candidate against M04 baselines.

Minimum gate inputs:

candidate model name
candidate metrics
baseline metrics
evaluation window
feature version
training window
metric names
selection result
reason
created timestamp UTC

Suggested default gate:

candidate MAE must be less than or equal to the selected baseline MAE
candidate WAPE must be less than or equal to the selected baseline WAPE where available
candidate must not fail slice-level sanity checks
candidate must have reproducible lineage
candidate must not use leakage-prone features

The exact thresholds may be conservative and configurable.

A failing candidate should be persisted as evaluated but not selected.

Recommended Codex Breakdown

M05 should be broken into controlled implementation chunks.

Recommended order:

M05-C01 — Forecast Output Contracts and Model Metadata Schema

Define forecast output contracts, model metadata, model training run tables, model artifact tables, forecast output tables, quantile fields, peak/ramp fields, and lineage. Add migration and tests. No training yet.

M05-C02 — Candidate Training Pipeline

Train a simple production candidate using M04 feature snapshots. Compare against baseline metrics. Keep it deterministic and reproducible.

M05-C03 — Model Selection and Artifact Persistence

Add model-selection gates, artifact saving/loading, metadata persistence, artifact reload tests, and reproducibility checks. No deployment.

M05-C04 — Forecast Generation Foundation

Generate forecast outputs from selected model artifacts using M04 issue contracts and feature snapshots. Include P50 or point forecast output and optional P10/P90 if safely implemented.

M05-C05 — Monitoring Foundations, Runner, Documentation, Verification, and Handoff

Add performance/drift monitoring foundations, runner commands, final documentation, verification report, handoff, and update repository state.

The milestone lead may adjust these chunks after repository inspection.
