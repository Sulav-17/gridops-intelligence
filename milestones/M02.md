Objective

Build the first production-style ingestion foundation for GridOps Intelligence.

M02 must acquire, archive, normalize, and track representative electricity and weather sources with raw snapshot preservation, source metadata, ingestion-run tracking, idempotent loading, basic revision evidence, deterministic tests, documentation, verification, and handoff.

The goal is not to build the final orchestration platform. The goal is to create the ingestion foundation that later milestones can trust.

Completion Statement

M02 succeeds when representative ingestion runs can be executed repeatedly without duplicate normalized facts, while preserving immutable raw evidence, source metadata, ingestion-run status, parser evidence, and source-native fields.

M02 must be strong enough for M03 to add formal data-quality checks and observability on top of it.

High-Level Design

M02 should establish the first Bronze and Silver ingestion foundation.

Bronze

Bronze preserves source evidence.

Bronze should track:

ingestion runs
raw snapshots
source name
source type
source URL or retrieval identifier
retrieval timestamp UTC
publication timestamp when available
content hash
content type
parser version
storage path
ingestion status
failure details when safe to store
Silver

Silver contains normalized records that remain traceable to Bronze.

Silver should include:

normalized timestamps
normalized values
source-native fields
source snapshot reference
ingestion run reference
row hash or equivalent revision evidence
current versus superseded state where practical

Silver should not become Gold.

Do not create forecasting features, model tables, alert tables, dashboard tables, or scenario tables in M02.

Fixture-First Rule

Automated tests must not depend on live internet.

Use:

local fixtures
mocked HTTP responses
temporary directories
isolated test database setup
deterministic sample payloads

Live source checks may be documented as optional smoke commands, but CI and normal tests must remain deterministic.

If official live source URLs, source schemas, or weather provider details are uncertain, implement fixture-backed adapters and document the assumption. Do not invent live-source behavior.

Required Design Principles
Raw Snapshots Are Immutable

Fetched or fixture-loaded payloads must be stored as immutable raw snapshots.

A raw snapshot must include enough metadata to trace:

what was retrieved
where it came from
when it was retrieved
how it was hashed
which parser version handled it
which ingestion run created it

Identical raw payloads should not be duplicated unnecessarily.

Do not commit live downloaded raw data files.

Loading Must Be Idempotent

Rerunning the same successful ingestion against the same payload must not create duplicate normalized records.

Tests must prove this.

Revision Handling Must Be Basic but Explicit

M02 does not need complex bitemporal history.

M02 does need clear changed-record evidence.

For the same source-native key, if values change:

preserve the raw snapshot evidence
compute row-level revision evidence
mark or identify the latest current record where practical
avoid silent overwrites without traceability
document the chosen behavior
Failures Must Be Recorded Safely

If fetch, parse, or load fails:

record the ingestion run failure
avoid corrupting existing records
avoid leaking secrets in error messages
expose enough safe detail to debug the problem

Runner Requirements

Add simple documented ingestion commands.

A simple Python module runner is enough.

Acceptable command pattern:

uv run python -m gridops.ingestion.runner --source ieso-demand --mode fixture --path tests/fixtures/ingestion/ieso/hourly_demand_sample.csv

uv run python -m gridops.ingestion.runner --source weather-observations --mode fixture --path tests/fixtures/ingestion/weather/observations_sample.csv

Optional live smoke commands may be documented separately, but they must not be required for automated tests.

Do not introduce Typer, Click, Prefect, or another orchestration dependency unless clearly justified and approved by the project owner.
