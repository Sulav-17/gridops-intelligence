# M06 Alert Rules

## Status

This document covers the M06 fast-track chunk 1 alert foundation. It does not mark the full M06 milestone complete.

## Alert Types

- `high_demand`: forecasted demand exceeds a fixed decision-support threshold.
- `ramp`: adjacent forecast intervals have a large expected MW change.
- `forecast_deviation`: current forecast differs materially from the previous succeeded forecast run for the same target interval.
- `source_health`: persisted M03 quality/source-health state indicates decision-support context.
- `combined_context`: deterministic component signals occur together, currently forecast attention plus source-health context.

## Severities

- `info`: non-urgent context.
- `watch`: condition worth monitoring.
- `warning`: meaningful attention condition.
- `critical`: severe decision-support attention condition.

These severities are not official IESO emergency or reliability categories.

## Lifecycle States

- `open`: active alert generated by deterministic evaluation.
- `acknowledged`: active alert reviewed by an operator or downstream workflow.
- `resolved`: historical alert whose condition has been handled or cleared.
- `suppressed`: historical alert intentionally suppressed.
- `expired`: historical alert no longer current.

Valid transitions:

- `open` to `acknowledged`, `resolved`, `suppressed`, or `expired`
- `acknowledged` to `resolved`, `suppressed`, or `expired`

Resolved, suppressed, and expired alerts are terminal in this chunk.

## Thresholds

The initial thresholds are conservative fixed values for deterministic local decision support:

- high-demand warning: `24000.000 MW`
- high-demand critical: `26000.000 MW`
- ramp warning: `1000.000 MW`
- ramp critical: `1500.000 MW`
- previous-forecast deviation warning: `750.000 MW`
- previous-forecast deviation critical: `1250.000 MW`

These thresholds are documented product thresholds, not official emergency thresholds.

## Evidence Fields

Every persisted alert stores current structured evidence, and every evaluation stores an immutable `alert_evidence` row. Evidence includes where applicable:

- alert rule name
- alert type and severity
- policy version
- production forecast run ID
- forecast issue time UTC
- target interval start and end UTC
- forecast value
- threshold used
- comparison result
- M05 prediction fields, including nullable P10/P90
- ramp value, absolute ramp, direction, and ramp source
- comparison forecast run and prediction for deviation alerts
- M03 dataset name, quality status, source-health status, and safe failure summaries
- component signal fingerprints for combined-context alerts
- generated timestamp UTC
- safe explanation text

## Duplicate Prevention

Alert fingerprints are deterministic SHA-256 hashes over business identity fields only. They do not include database IDs, random values, or processing timestamps.

The database has a partial unique index on active alert fingerprints where state is `open` or `acknowledged`. Re-evaluating the same condition against the same source evidence and policy reuses the active alert and appends new evidence instead of creating a duplicate active alert.

## Source-Health Context Behavior

Source-health alerts reuse M03 persisted quality runs and results through the existing source-health summary service.

- blocked datasets or failed quality runs produce `critical`
- `critical` worst severity produces `critical`
- `error` worst severity produces `warning`
- `warning` worst severity produces `watch`
- datasets with no quality run do not generate alerts

This does not redesign or replace M03 quality checks.

## Known Limitations

- Prediction interval and confidence alerts are deferred because M05 stores nullable P10/P90 fields but does not generate true quantile forecasts or confidence indicators.
- Forecast deviation uses the previous succeeded production forecast run, not actuals or seasonal expectation.
- Combined-context alerts are intentionally simple and only combine deterministic forecast attention signals with source-health context.
- No notification system, ticketing system, dashboard, alert API, scenario engine, briefing generator, or runner command is implemented in this chunk.
